## 先建立四个概念

程序是一组可执行的规则；函数是给规则起一个名字并定义输入和输出；文件把规则组织起来；终端让你明确告诉电脑执行哪个程序。编辑器修改文件，终端执行文件，浏览器展示网页，这三个窗口各有职责。

在小事板中，浏览器并不直接写数据库。点击「添加」后，`app.js` 把标题编码为 JSON，发送 HTTP 请求；`server.py` 选择处理方法，`domain.py` 校验标题，`store.py` 保存进 SQLite，最后把结果返回浏览器。HTTP 是请求与响应的约定，JSON 是数据写法，数据库负责跨重启保存记录。

不要急着背所有代码。先用一个具体动作追踪数据：输入「读书」，哪里取到它，哪里检查它，哪里保存它？每一步只回答一个问题。

## 跟做：用 Python 验证想法

完成 [环境准备](setup-git.md)。在根目录运行 `python` 进入交互窗口，依次输入：

```python
title = "  读书  "
print(title.strip())
from app.domain import clean_title
print(clean_title(title))
print(clean_title("   "))
```

前两次输出都是「读书」，最后一次抛出 `ValueError`。异常并不总是程序失控，它也可以表示主动拒绝不合法的输入。阅读 traceback 时，从最后一行看错误类型和原因，再往上找自己项目的文件。

继续输入：

```python
from app.domain import extract_tasks
print(extract_tasks("- 读书\n天气不错\n待办：跑步"))
```

输出列表包含两个元素。这里 `\n` 表示换行，列表保留元素顺序。`exit()` 离开交互窗口；命令行出现 `>>>` 时不能直接输入 `git status`。

## 必做练习：加入一个新的任务标记

目标：在现有 `- `、`* `、`TODO:`、`待办：` 之外，让 `任务：读书` 也能被提取。

1. 运行 `python -m unittest discover -s tests -v`，记录基线成功。
2. 打开 `tests/test_app.py`，在 `DomainTests` 中新增测试方法：`self.assertEqual(extract_tasks('任务：读书'), ['读书'])`。
3. 再跑一次。这次应失败；失败说明新增的需求还没实现。
4. 找到 `app/domain.py` 的前缀列表，仅加入 `"任务："`。再跑测试，应全部通过。
5. 启动网页试一次；同时确认原有 `TODO:` 仍然有效。
6. 用 Git 保存，或者将修改前后的两个文件单独备份。写清「增加任务前缀」，不要写「改了一些东西」。

先加测试再改实现，让你知道测试有能力抓住这个缺失。如果第一次运行就绿了，检查你是不是只验证了旧行为。测试的意义是发现违约，而不是让终端好看。

## 读懂这五类语法就能继续

| 语法 | 本项目中的含义 | 小练习 |
| --- | --- | --- |
| `def` / `return` | 定义函数 / 交还结果 | 把返回值赋给变量 |
| `if` | 条件满足时执行 | 预测空字符串走哪个分支 |
| `for` | 按顺序处理列表 | 逐行打印一段笔记 |
| `dict` / `list` | 字段集合 / 有序集合 | 找到任务的 title 和 done |
| `raise` / `try` | 报告异常 / 处理异常 | 故意提交空标题 |

想深入时看 [Python 官方教程](https://docs.python.org/3.12/tutorial/)，先读控制流和数据结构，不必先学完所有 Python。

## 验收与自检

交一张应用截图、一段测试的真实输出、修改说明。必须能解释「刷新后任务仍存在」与「提取预览尚未保存」有什么不同。

自检：测试失败是不是一定要删掉测试？数据库文件为什么不应随作业提交？修改网页文字需要重建 Python 环境吗？

参考答案：先确认需求和断言，再修实现；数据库可能含个人练习内容，而且测试应使用隔离数据；静态文案修改后刷新即可，当前教学服务器每次读取静态文件。

遇到困难：[排错指南](../docs/troubleshooting.md)。进入选学 S01前，只要求你能解释自己这次修改，不要求读懂全部服务器实现。
