# 常用词，用小事板理解

| 词 | 一句话说明 | 在项目中的例子 |
| --- | --- | --- |
| Repository / 仓库 | 文件与版本历史的集合 | 本课程与自己的 Fork |
| Commit / 提交 | 保存一次有解释的变更 | 增加小写前缀支持 |
| Branch / 分支 | 独立推进一组修改的历史指针 | feature/filter |
| PR | 请求比较、讨论、合并一组修改 | 筛选功能评审 |
| API | 程序之间约定的调用接口 | POST /api/tasks |
| JSON | 文本形式的数据表示 | title 与 done 的对象 |
| Schema / 契约 | 对数据结构和规则的约定 | done 必须是布尔值 |
| CRUD | 创建、读取、更新、删除 | 小事板四个基本动作 |
| Persistence / 持久化 | 程序重启后数据仍在 | SQLite 文件 |
| LLM | 从上下文生成内容的语言模型 | 可选自然语言任务提取 |
| Context / 上下文 | 本次模型能够看到的信息 | 规格、代码、错误输出 |
| Token | 模型处理文本的计量单元之一 | 不等于一个汉字或一个单词 |
| Agent | 模型与工具、状态、控制循环组成的系统 | 读文件→修改→运行测试 |
| Tool calling | 模型提出结构化调用，由执行器运行 | 调用 list_tasks |
| MCP | 宿主接入外部能力的协议 | 客户端发现两个任务工具 |
| RAG | 先取相关资料，再据此生成回答 | 提供任务判定规范 |
| Eval | 用固定任务和标准评价结果 | 比较 A/B 提示输出 |
| Stub / 替身 | 用可控响应替换真实外部服务 | 假 provider 返回无效 JSON |
| Unit / Integration test | 局部规则测试 / 多层联合测试 | 提取函数 / HTTP 与数据库 |
| CI | 在提交或 PR 时自动重复检查 | GitHub Actions |
| Regression / 回归 | 原先有效行为在修改后坏了 | 大写 TODO 不再被识别 |
| SAST / SCA | 静态代码分析 / 依赖成分分析 | 拼接 SQL / 包版本核查 |
| Observability | 根据系统信号理解内部状态 | 请求编号、状态码、耗时 |
| Rollback / 回滚 | 回到已知可工作的版本或状态 | 撤回坏提交，必要时恢复备份 |
| Idempotency / 幂等 | 重复执行仍保持预期状态 | 创建已存在目录不重复增加内容 |

遇到生词先找到一个实际输入输出，再学习正式定义。能复述术语不等于能识别工程风险。
