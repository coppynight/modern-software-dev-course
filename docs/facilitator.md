# 小组共学与带课指南

适合 4–12 人的学习小组，也可用于个人安排。每周一次 90 分钟共学，另留 3–4 小时个人练习。学习成果按行为与证据评价，不按工具品牌和订阅档位分层。

## 开课前

让每位学员跑第 0 课；收集系统版本与一个具体卡点。没有通过基本启动的同学先参加环境互助，不要让第一次共学全部消耗在安装。确定一个可用的答疑渠道；课程本身不要求使用指定社交平台。

## 每次 90 分钟

前 10 分钟复盘上次失败；20 分钟讲一个核心模型；20 分钟现场演示并故意触发一次错误；25 分钟两人实践；最后 15 分钟交换证据和布置必做。进阶任务只给已经完成基础验收的同学。

| 周次 | 主持时重点追问 | 观察到困难时如何缩小 |
| --- | --- | --- |
| 1 | 你怎么知道答案对？ | 从一个输入和一个明确预期开始 |
| 2 | 是模型说了，还是工具执行了？ | 只追踪一次调用 |
| 3 | 助手还缺哪项信息？ | 只给一份规格与三个相关文件 |
| 4 | 这套流程实际跑过吗？ | 先做「检查失败就停止」 |
| 5 | 两份修改如何安全汇合？ | 放弃并行，先串行两小任务 |
| 6 | 风险从哪个输入走到哪个操作？ | 只分析一个具体反例 |
| 7 | 你的意见能复现吗？ | 把意见转成测试或操作步骤 |
| 8 | 用户哪里停下来？ | 观察一个人完成一个任务 |
| 9 | 服务恢复的证据是什么？ | 分开健康、数据读取、实际写入 |
| 10 | 别人能照 README 运行吗？ | 换干净目录交叉复现 |

## 反馈方法

先复述学员目标，再指出一个最影响正确性的差距，最后给一个小实验。避免把「AI 没懂」当作结论，继续问输入、规格、工具与证据。允许写「不知道」「未运行」「没有模型账号」，不鼓励为拿分伪造经历。

共学每两周做一次范围复盘：是否还在同一条主线？是否因为追工具热点增加了不必要安装？对于慢速线，两次活动完成一课，保留所有验收，减少进阶。

## 毕业互评

两人交换干净仓库与 README。复现者记录所有额外口头提示，作者据此补文档；按 [评分表](assessment.md) 判断。展示可以是本地演示或录屏，不要求公众部署，不发布未经允许的个人资料。
