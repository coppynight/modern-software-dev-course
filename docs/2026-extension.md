## 扩展 A：真实轨迹解剖（2–3 小时）

选一个包含多文件修改、一次失败、显式计划的个人练习任务。使用工具本身提供的可导出记录，或在你有权调试的本地试验环境按官方作业操作。不要捕获工作项目或其他人的会话；原始捕获保持本地，不随报告提交。

报告只保留脱敏后的最小片段：工具名、关键参数类型、结果状态、时间顺序。对每个结论写 `[OBSERVED]`（片段直接支持）或 `[INFERRED]`（基于间接证据推断）。没有触发子 Agent 或上下文压缩就写未观察，不能根据工具存在推断它被执行。

验收：一条失败→恢复链、两种不同工具的设计分析、一个你将改变的使用习惯。没有真实轨迹时可用 `labs.agent_trace` 学分析格式，但必须标成教学模拟。

## 扩展 B：Agent 友好度审计（90 分钟）

让一个全新会话仅凭 README 找启动方式和测试命令，记录卡点。用 0/1 检查：入口明确、依赖明确、可隔离测试、错误可读、接口有契约、文档与行为一致、日志可定位、凭据不在仓库。优先修两项真实阻碍，再重复同一任务观察差异。

这是本课程自定义诊断表，不是 Stanford 或行业认证分数。

## 扩展 C：有限预算的后台流程（2 小时）

为一条低风险 issue 设计自动流程：读取规格→创建隔离分支→修改→测试→生成待评审变更。限制可写目录、调用轮数、总耗时和失败重试次数；把「规格不清」「权限不足」「重复失败」列为交还人的条件。

单人可以手动模拟触发，不需要真的购买后台服务。真实运行时记录总成本、返工与人工介入，不把一个成功样例外推为完全无人开发。

## 扩展 D：小团队运行规则（90 分钟）

用一页表格说明：哪些工具只读，哪些能改共享状态；谁决定模型与预算；什么数据允许进入上下文；谁审查发布；失败怎么回滚。选择一个可衡量问题，例如 PR 等待时间或重复环境报错，先试两周再决定是否扩大使用。

所有扩展练习均为本项目新编；上表主题来自公开大纲。没有把预告嘉宾的观点或未来讲义编造成课程事实。
