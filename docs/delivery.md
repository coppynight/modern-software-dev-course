# 从本地交付到公网部署

## 基础线：别人能复现的本地版本

清理工作区并提交需要的文件，记录版本。让同伴从干净目录按 README 运行 `python tools/check.py` 与 `python -m app.server`。保留其操作中的卡点并更新文档。ZIP 只包含代码、文档、固定假数据，不包含 `.git`、数据库、日志、密钥、虚拟环境。

GitHub 仓库保存的是代码。提交 Actions 工作流并不等于检查已经在 GitHub 上执行，更不等于应用已经部署。GitHub Pages 只能直接托管静态内容，不能运行本课程的 Python 后端。

## 进阶：真正对外提供服务

本项目使用 Python 标准库教学 HTTP 服务器，默认只监听回环地址；Python 官方不建议将该服务器作为生产服务器。若要上线，应将领域逻辑与数据访问迁移到适合部署的 Web 框架/服务器，并按目标平台文档配置。课程不提供把监听地址简单改成 0.0.0.0 的上线捷径。

| 能力 | 为什么需要 | 交付证据 |
| --- | --- | --- |
| 登录、权限、用户数据隔离 | 区分谁能读改谁的任务 | 两用户越权测试 |
| TLS、配置与凭据管理 | 保护传输与环境差异 | HTTPS 与不含密钥的部署配置 |
| 输入/请求限制、CSRF 等防护 | 服务暴露面扩大 | 依据实际认证方式制定并验证策略 |
| 持久卷/数据库与备份 | 重启和发布后数据可用 | 重启、备份、恢复验证 |
| 生产进程与健康/就绪检查 | 能被托管与监测 | 进程重启、存储故障演练 |
| 日志、指标、回滚路径 | 问题可定位可恢复 | 发布前后检查与恢复记录 |

不要把完成这张表等同于全面安全审计。上线范围根据实际用户、数据与平台能力决定。对爱好者而言，先完成一份可复现的本地交付已经是有价值的毕业成果。
