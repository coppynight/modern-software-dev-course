# 现代软件开发：用 AI 完成一次可靠交付

**5 个实战单元，建议 8–12 小时。基础知识按需选学。**

围绕一个小功能，走完「明确需求 → Agent 实现 → 工作流 → 评审验证 → 交付」。主线只讲这条路径上需要的判断与方法。Python、终端和 Git 基础保留在选学区，不需要从头学完才能开始。

## 从这里开始

已有基础编程经验：读 [5 分钟准备](docs/start.md)，直接进入主线。运行、语法或 Git 操作卡住时，再查 [选学与补课目录](optional/README.md)。

可以使用自己的熟悉项目；没有合适项目就用附带的「小事板」。示例采用 Python，只作为实践载体，不要求更换日常技术栈。不限定 AI 工具，不要求购买指定套餐。

| 单元 | 关键问题 | 本次产出 |
| --- | --- | --- |
| [1. 把需求交代清楚](lessons/01-spec.md) | 如何提供规格、上下文和验收标准？ | 半页任务卡 |
| [2. 让 Agent 做小步实现](lessons/02-build.md) | 怎样控制工具调用、修改范围和失败恢复？ | 一个可运行的功能 |
| [3. 建立可重复工作流](lessons/03-workflow.md) | 怎样减少重复解释与检查？ | 项目说明与检查入口 |
| [4. 判断代码是否可靠](lessons/04-review.md) | 怎样结合人工、AI、测试与安全检查？ | 一次有证据的评审 |
| [5. 完成一次交付](lessons/05-deliver.md) | 别人能否运行、使用并恢复它？ | 一个可复现 PR 或版本 |

**全程只维护一份 [任务卡](templates/task-card.md) 和同一个功能。** 不要求周报、多个技术栈或额外毕业项目；选学不影响主线完成。最后用 [完成清单](docs/assessment.md) 自检。

## 运行示例

在仓库根目录，使用 Python 3.12：

```bash
python3 tools/check.py
python3 -m app.server
```

打开 <http://127.0.0.1:8000>。Windows 可将 `python3` 替换为 `py -3.12`。这是本地单用户教学应用，公网部署需另行补齐生产能力。
