# 5. 完成一次交付

[上一单元](04-review.md) · [首页](../README.md)

**约 2 小时。产出：可复现的 PR 或版本，不另做毕业项目。**

## 从代码通过到别人能用

用户关心结果与下一步。筛选成功、结果为空、请求失败都需要反馈；按钮接了接口不等于流程可用。交付者还需要知道怎么启动、出问题看什么、如何回到可工作的状态。

## 动手：完成四项检查

1. **使用：**切换三种筛选、修改任务完成状态、观察空列表；用键盘和窄窗口各走一次核心流程。能找试用者就观察一次，找不到则明确记录自测。
2. **失败：**停止服务再操作，检查页面是否解释失败并保留必要输入。重启后确认原数据仍在，读写功能恢复。
3. **复现：**从干净目录按 README 启动并检查，不借用旧目录中的环境和数据。补齐缺失步骤。
4. **交付：**整理一个小 PR 或版本，说明需求、实现、真实验证、限制和一项关键判断。用 [完成清单](../docs/assessment.md) 收尾。

本地交付满足主线，不要求购买云服务或部署公网。附带服务器仅用于本地单用户教学；需对外提供服务时再读 [交付进阶](../docs/delivery.md)。

## 运维先抓住两个区别

健康接口能响应，不等于用户流程可用；撤回代码，不等于恢复数据。简单恢复说明至少写明启动命令、业务验证和数据保护方式。助手可以提出诊断假设，不能把未经验证的猜测直接变成破坏性修复。

需要深入时再用 `tools/log_summary.py` 看请求、错误与耗时。本轮不要求额外指标报告或完整事故复盘。

**完成标准：**别人按文档能运行功能；成功与失败路径已检查；交付内容不含凭据或个人数据；能解释一次采纳或修正 AI 建议的原因。
