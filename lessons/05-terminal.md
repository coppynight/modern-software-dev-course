# 第 5 课：终端、脚本与可合并的小任务

[上一课](04-workflows.md) · [首页](../README.md) · [下一课](06-security.md)

**4–6 小时。** 目标：理解可重复命令、分支隔离和失败退出；完成一次小任务合并。交付：命令清单、两个分支的记录和一键检查。

## 核心讲解

终端是明确输入与明确输出的界面。目录决定相对路径指向哪里，环境决定解释器和依赖来自哪里，退出码决定流程是否继续。让助手生成命令前，先让它解释会读写哪些文件。不了解含义的命令不应直接复制执行。

脚本把固定步骤写成程序；工作流决定什么时候运行脚本、失败怎么处理。重复运行不会产生额外破坏称为幂等。例如「确保输出目录存在」可以幂等，「每次往文件末尾追加同一段内容」通常不是。

分支隔离修改历史，worktree 给同一仓库的不同分支提供不同工作目录。它不是权限沙箱，也不隔离外部数据库、环境变量或网络。两个 worktree 若都连同一个数据库，仍可能互相影响。

## 跟做：检查当前状态

```bash
git status
git diff --stat
python tools/check.py
```

理解输出后，练习 `git diff -- app/domain.py` 和 `git log --oneline -5`。查看文件、测试与历史是只读诊断；撤销命令会改变内容，使用前先确认本地未提交修改是否需要保留。

## 必做：两个可独立交付的任务

任务 A：为任务列表添加筛选，若第 3 周已实现，就补非法值测试与文档。任务 B：新增 JSON 导出功能，只导出 `id/title/done`，不导出数据库路径或内部调试信息。

基础线可以串行：从主分支建 `feature/filter`，完成、测试、合并；再从合并后的主分支建 `feature/export`。每次只合并一个小功能。

进阶可以隔离并行；以下命令假定当前本地分支是 `main`，执行前先用 `git branch --show-current` 确认：

```bash
git worktree add ../course-filter -b feature/filter main
git worktree add ../course-export -b feature/export main
```

分别给两边助手明确文件责任与 API 契约。若都需要修改 `server.py`，先预测冲突，选择串行集成或由同一人改路由。工作树默认各自使用目录下 `data/tasks.db`；不要手动指定到同一绝对数据库路径。

完成后每边提交。回主工作目录，确保没有未提交修改，逐个 `git merge feature/filter`、检查、再合并另一个。若产生冲突，先理解两边目的再编辑，不要盲选 ours/theirs。已确认需要暂缓时可用 `git merge --abort` 取消当前合并；先保留需要的修改。

## 改善自己的自动化

让导出命令在指定输出已存在时明确报错，除非用户显式传 `--overwrite`。测试空列表、中文、重复执行、非法输出路径。使用 Python 的文件 API，避免为拼接用户输入调用 shell。

把验证接到 `tools/check.py` 或独立脚本，再接入 GitHub Actions。CI 是别人机器上的重复验证，不证明浏览器交互正确，也不自动部署应用。写出同一命令在本机与 CI 的结果。

## 验收与答案

提交两个小变更、检查输出、一次合并记录。对比串行与并行时写真实总耗时，包含冲突处理；没有测量就写定性观察，不编造节省百分比。

自检：分支能隔离共享数据库吗？为什么脚本失败后仍退出 0 很危险？把可重复命令放聊天记录有什么缺点？

答案：不能；CI 可能误以为成功；难以版本化、检查和复现，应落到仓库中。
