# 第 10 课：交付一个可解释、可运行的作品

[上一课](09-operations.md) · [首页](../README.md)

**4–6 小时；毕业项目的功能在前几周逐步完成。** 目标：让另一位学习者复现你的作品，并说明 AI 参与的价值与边界。

## 从教程跟做到个人作品

从一个具体人和具体场景出发：为自己整理学习计划、帮家庭记录待办、给读书小组整理讨论行动。任选一个，不同时做社区、支付、推荐和复杂账号体系。小而完整的成果更容易验证，也更能暴露真实工程问题。

毕业不是把起始项目原样提交。至少新增两个有用户价值的行为，例如筛选与导出、候选编辑与撤销、截止日期与排序。每个行为写出需求、失败条件和验收；避免用换背景色凑数量。

## 最小交付范围

- 一个清晰用户任务和一个主要数据实体；创建、读取、修改、删除与持久化正常。
- 至少两个自己实现的行为，包含边界处理与对应验证。
- 使用者能理解的界面状态，至少一次真实试用或明确标注的自测。
- 从干净目录可运行的 README、检查命令、数据初始化与停止方法。
- 一份评审记录、一份恢复演练、一份 AI/人工分工记录。

详细评分见 [毕业评分表](../docs/assessment.md)。这是本项目自定义评分，不是 Stanford 的评分标准。

## 必做：干净目录交付

1. 确认提交中没有数据库、密钥、聊天原始请求或个人信息。审查 `git diff --cached`，而不只相信 `.gitignore`。
2. 在干净目录克隆自己的提交或解压发布包；只按 README 安装与运行，不借用旧目录的环境。
3. 运行统一检查；启动应用，完成完整用户任务；停止并重启，确认持久化。
4. 在文档写明确已验证的平台与版本。只测了 Linux，就不要声称 Mac 和 Windows 均测试通过。
5. 标记版本，比如 `v0.1.0`；把版本、提交号、已知限制放进发布说明。

默认交付是可复现的本地包，不要求购买域名或云服务器。希望公网部署的学员按 [交付指南](../docs/delivery.md) 先补生产服务器、认证授权、TLS 与备份等必要能力；单纯转发本地端口不算生产就绪。

## 五分钟演示脚本

第 1 分钟说明用户和问题；第 2 分钟演示核心任务；第 3 分钟演示一个真实失败及恢复；第 4 分钟说明一次你拒绝或修正 AI 的地方；第 5 分钟展示干净运行证据与下阶段取舍。

不要把演示时间都花在工具名。观众需要知道功能是否可靠、你做了哪些判断。如果没有调用过 AI，展示基础线成果并说明待补的对照实验。

## 复盘：未来值得保留的能力

工具会变化，表达意图、缩小变更范围、设计验证、解释失败、保护数据和交付协作成果的能力更容易迁移。写下三个自己将继续使用的习惯，并指出一个目前仍不愿交给 Agent 自主处理的环节及原因。

还可以比较两次真实任务的总投入：需求澄清、等待、手工修改、评审、返工都算时间。AI 生成速度只是其中一个部分。没有对照证据时，给出观察而非「效率提升十倍」的结论。

自检：作品不够大是否意味着不合格？起始测试全通过能否替代新增需求验证？为什么已知限制应写进发布说明？

答案：完整、可解释和可复现比体量重要；不能；使用者据此判断适用范围，维护者也能知道下一步真正需要解决什么。
